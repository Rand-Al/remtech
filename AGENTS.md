# RemTech: инструкция для продолжения разработки

## С чего начинать

Перед любыми изменениями:

1. Прочитай `DEVELOPMENT_PLAN.md` целиком. Это основной документ проекта.
2. Прочитай `CONTINUE_HERE.md`: в нём зафиксирована точная точка продолжения на другом компьютере.
3. Изучи текущие файлы в `design-prototype/` и не предполагай, что прототип соответствует старым сообщениям или макетам.
4. Открой текущую страницу в браузере и визуально проверь область, которую собираешься менять.
5. Учитывай, что пользователь хочет контролировать разработку маленькими шагами.

## Формат работы с пользователем

- Общайся с пользователем на русском языке.
- Текст интерфейса сайта по умолчанию должен быть на украинском.
- Не бери сразу несколько крупных блоков.
- Делай один небольшой фрагмент, проверяй его и показывай пользователю.
- После каждого визуального фрагмента спрашивай, оставляем его или нужно исправить.
- Не меняй уже утвержденные части без явной причины и согласования.
- Если пользователь показывает скриншот, сначала найди конкретную визуальную проблему, затем исправляй только ее.
- Не останавливайся на предложении, если пользователь уже разрешил внести изменение.

## Текущий этап

В проекте две части: утверждённый визуальный прототип (статический) и новый рабочий прототип (этап 1).

Статический прототип (`design-prototype/`) — утверждённый визуал для справки:

- Локальный адрес: `http://127.0.0.1:4174/`.
- Корень прототипа: `design-prototype/`.
- Общие стили: `design-prototype/styles.css`.
- Общая логика интерфейса и имитации чата: `design-prototype/prototype.js`.
- Основной язык: украинский.
- Этап 4 (полная украинская версия) завершён: главная, котлы, стиральные машины, посудомоечные машины, политика конфиденциальности, шапка/подвал/чат, работы, отзывы, FAQ, адаптивность и базовый SEO.
- Этап 5 (полная русская версия) завершён: все страницы переведены на русский (`/ru/`), переключатели языка UA/RU в шапке и подвале на всех страницах, автоопределение языка при первом визите, запоминание выбора языка, язык чата зависит от страницы, двусторонние `hreflang uk/ru` и свои `canonical` на всех страницах, sitemap.xml включает русские страницы.

Для локального просмотра прототипа:

```powershell
python -m http.server 4174 --directory design-prototype
```

Если порт занят уже работающим сервером, не запускай второй процесс на том же порту.

Новый рабочий прототип (`web/`) — Этап 1 (первый сквозной прототип) реализован:

- Next.js 16 + TypeScript сайт: `web/`, dev на `http://localhost:3000/`.
- Украинская страница `/kotly/` перенесена из прототипа (все секции, metadata, визуал из `design-prototype/styles.css` → `app/globals.css`).
- Главная `/` перенесена из прототипа: hero, услуги (котлы + пральные + посудомойные + «інша техніка»), FAQ-аккордеон (`components/Faq.tsx`), контакты, шапка/подвал/чат. `page.module.css` удалён.
- PostgreSQL 17 в Docker: `web/docker-compose.yml`, `docker compose up -d`. Схема `web/db/schema.sql` монтируется в `/docker-entrypoint-initdb.d` и применяется автоматически при первом старте (пересоздать: `docker compose down -v && docker compose up -d`).
- Отдельный Node.js-сервер чата: `web/chat-server/`, dev на `http://localhost:4100/` (`npm run dev` из `web/chat-server`).
  - Маршруты: `POST /api/chat`, `POST /api/agent-reply`, `GET /health`.
  - Безопасность: заявки идентифицируются непредсказуемым токеном (UUID в `requests.token`), клиент не знает числовой id; несуществующий токен → «Заявку не знайдено».
  - Ограничения: длина сообщения ≤ 4000 символов; история для LLM ограничена последними 20 сообщениями; payload > 1МБ → 413 и обрыв соединения.
  - Telegram-карточка отправляется только после появления телефона или имени у клиента (поле `phone` извлекается из текста), отправляется один раз (`requests.telegram_notified`).
  - Сменные адаптеры через `web/chat-server/src/adapters.ts`: `llm/` (StubLlmAdapter — заглушка, реальный провайдер подключается позже) и `telegram/` (StubTelegramAdapter — лог в консоль).
  - Системный промпт не передаётся клиенту; при сбое LLM клиент видит «Дякуємо, повідомлення отримано. Менеджер відповість трохи пізніше.», событие пишется в `technical_events`, уведомление уходит в Telegram-адаптер.
  - Скрытый контекст услуги передаётся в `serviceToContext` (`web/chat-server/src/index.ts`).
- Клиентский чат: `web/components/ChatPanel.tsx`, ходит на `NEXT_PUBLIC_CHAT_SERVER_URL` (из `web/.env.local`).
  - Разговор сохраняется в `sessionStorage` (`remtech-chat-v1`) и продолжается между переходами по страницам.
  - Подключение менеджера запускается один раз; повторное открытие панели не сбрасывает статус в «підключення...».
  - Анимация «друкує...» (3 точки) для приветствия и каждого ответа менеджера, задержка по количеству слов (1.6–6.5с).
  - На мобильном панель — полноэкранное модальное окно (`aria-modal="true"`, `body.chat-open` блокирует прокрутку фона).
  - Enter отправляет сообщение, Shift+Enter — перенос строки; textarea растёт до 110px.
- LLM API и Telegram-бот ещё не готовы — используются заглушки, подключаются по ходу.

Запуск рабочего прототипа:

```powershell
# терминал 1: база данных
cd web && docker compose up -d
# терминал 2: чат-сервер
cd web/chat-server && npm run dev
# терминал 3: сайт
cd web && npm run dev
```

Проверка типов: `npm run typecheck` в `web/` и `web/chat-server/`; сборка сайта `npm run build` в `web/`.

### Русская версия

Все страницы продублированы на русском в `design-prototype/ru/` (`/ru/`, `/ru/kotly/`, `/ru/pralni-mashyny/`, `/ru/posudomyini-mashyny/`, `/ru/privacy/`). У каждой русской страницы `data-lang="ru"` на `body`, свой `canonical` и двусторонние `hreflang uk/ru`.

Механизм языков реализован в `prototype.js`:

- `pageLang` берется из `body[data-lang]` (по умолчанию `uk`), строки чата/меню/статусов подставляются из словарей `i18n.uk` и `i18n.ru`;
- автоопределение языка при первом визите: если у браузера язык `ru` и нет сохраненного выбора, украинская страница перенаправляет на русский аналог, и наоборот;
- выбор языка запоминается в `localStorage` (`remtech-lang-choice`) при клике на UA/RU в шапке или подвале;
- при переключении языка позиция прокрутки сохраняется в `sessionStorage` (`remtech-lang-scroll`) и восстанавливается на новой странице;
- переключатели UA/RU есть в шапке и подвале на всех страницах и ведут на парную страницу.

## Утвержденные решения

- Бренд: `RemTech`.
- География: Бровары и Броварской район.
- Основной акцент: оранжевый.
- Дополнительный цвет: бирюзовый.
- Цвета в будущем должны переключаться через админку.
- Основные услуги: котлы, стиральные и посудомоечные машины.
- Выезд и диагностика оплачиваются отдельно.
- Стоимость ремонта определяется после осмотра и согласуется до начала работ.
- Не использовать тему «дешево/дорого».
- Тон сайта теплый, спокойный и уважительный, обращение на «вы».
- Не показывать клиенту внутренние инструкции, фильтры, логику LLM или фразы о том, что он разговаривает с роботом.
- Для клиента это обычный чат с менеджером RemTech.
- Менеджер не ставит диагноз онлайн и не дает инструкций по самостоятельному ремонту.
- На странице котлов нельзя советовать самостоятельную разборку газового оборудования.

## Чат

Текущий чат является интерфейсной имитацией, но его поведение уже утверждено:

- менеджер подключается с заметной задержкой;
- фаза `друкує...` зависит от длины сообщения;
- при переходе между страницами разговор продолжается;
- выбранная услуга не должна самопроизвольно меняться;
- оставшееся время подключения сохраняется между страницами;
- на мобильном чат открывается как модальное окно и блокирует фон;
- чат закрывается кнопкой, а на широком экране также кликом вне панели;
- можно выбрать фото или видео;
- технический контекст услуги передается скрыто от клиента.

Состояние хранится в `sessionStorage` под ключом `remtech-chat-session-v4`.

## Тестовые данные

В прототипе намеренно оставлены:

- тестовый номер телефона;
- тестовый Telegram;
- тестовый адрес на главной;
- тестовые цены;
- тестовые изображения работ;
- placeholder-домен `https://example.com/` в canonical, Open Graph, `robots.txt` и `sitemap.xml` — заменяется на реальный домен перед запуском.

Пользователь решил оставить тестовый номер кликабельным на этапе прототипа.

Тестовые цены и примеры работ должны быть скрыты в исходной разметке атрибутом `hidden` и показываться скриптом только на `localhost` или `127.0.0.1`.

## Визуальные ограничения

- Не использовать большие скругленные карточки и карточки внутри карточек.
- Не превращать рабочий сайт в маркетинговый лендинг с декоративными блоками.
- Не использовать декоративные шары, цветные пятна и тяжелые градиенты.
- Не делать интерфейс одноцветным: оранжевый только для главных действий, бирюзовый для статусов и вторичных акцентов.
- Не допускать наложения текста, кнопок и плавающего чата на важный контент.
- На мобильном текст hero должен находиться поверх изображения, а не отдельным блоком под картинкой.
- Заголовки и кнопки должны помещаться при ширине 390 пикселей.
- Все фиксированные элементы должны иметь устойчивые размеры и не сдвигать страницу при изменении состояния.

## Проверка после изменений

После каждого изменения:

1. Обнови параметр версии у `styles.css` или `prototype.js`, если соответствующий файл менялся, чтобы браузер не показывал старый кэш.
2. Проверь страницу в браузере, а не только исходный код.
3. Проверь широкую версию около 1400 пикселей.
4. Проверь мобильную версию около 390 пикселей.
5. Проверь отсутствие горизонтального переполнения и наложений.
6. Для изменений чата проверь сохранение разговора между страницами.
7. Не объявляй фрагмент завершенным до визуальной проверки.

## Будущая рабочая версия

Архитектура рабочей версии описана в `DEVELOPMENT_PLAN.md`. Планируется:

- новый frontend на Next.js и TypeScript;
- отдельный Node.js-сервис чата;
- PostgreSQL;
- объектное хранилище файлов;
- заменяемый адаптер LLM-провайдера;
- Telegram как первый канал передачи заявок;
- уведомления в Telegram при сбоях LLM, лимитов или сервера;
- админка для услуг, текстов, FAQ, цен, работ, отзывов, контактов, сезонного акцента и цветов;
- Docker-развертывание на Ubuntu-сервере.

Не начинай production-архитектуру, пока пользователь явно не завершил визуальный прототип и не разрешил перейти к следующему этапу.
